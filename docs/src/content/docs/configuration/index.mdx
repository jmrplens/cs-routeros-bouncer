cs-routeros-bouncer can be configured via **YAML file** and/or **environment variables**. Environment variables override values from the config file.

## Config file

When running the binary directly, pass the config path with `-c` unless all required settings are supplied via environment variables:

```bash
cs-routeros-bouncer -c /path/to/config.yaml
```

Deployment helpers choose their own paths:

| Deployment method       | Config path used                                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| `setup` systemd service | `/etc/cs-routeros-bouncer/cs-routeros-bouncer.yaml`                                                           |
| Docker image            | Environment variables by default; the implicit `/etc/cs-routeros-bouncer/config.yaml` is picked up if mounted |
| Direct binary execution | `-c` when given; otherwise `/etc/cs-routeros-bouncer/config.yaml` if that file exists                         |

The implicit `/etc/cs-routeros-bouncer/config.yaml` fallback is a property of the binary, not of the Docker image: any invocation without `-c` loads that file when it exists and otherwise runs in environment-variables-only mode.

YAML string values may contain explicit `${VAR}` placeholders. Only braced placeholders are expanded; literal `$` characters in secrets are preserved.

A full annotated reference is included in the repository at [`config/cs-routeros-bouncer.yaml`](https://github.com/jmrplens/cs-routeros-bouncer/blob/main/config/cs-routeros-bouncer.yaml).

## Quick reference

All options at a glance. See the dedicated pages for detailed descriptions.

### Basic parameters

The essential settings to get the bouncer running. Most deployments only need these.

<ConfigOption
  rows={[
    ["crowdsec.api_url", "CrowdSec LAPI URL"],
    ["crowdsec.api_key", "Bouncer API key"],
    ["mikrotik.address", "RouterOS API address (`host:port`)"],
    ["mikrotik.username", "API username"],
    ["mikrotik.password", "API password"],
    ["firewall.ipv4.enabled", "Enable IPv4 blocking"],
    ["firewall.ipv6.enabled", "Enable IPv6 blocking"],
    ["firewall.filter.enabled", "Create filter firewall rules"],
    ["firewall.raw.enabled", "Create raw/prerouting rules"],
    ["firewall.deny_action", "Action: `drop` or `reject`"],
    ["logging.level", "Log level: `debug`, `info`, `warn`, `error`"],
  ]}
/>

`mikrotik.address` and `mikrotik.username` have no built-in defaults. The `192.168.0.1:8728` and `crowdsec` values that appear in `config/cs-routeros-bouncer.yaml` are sample values, not defaults.

### Advanced parameters

Fine-tuning options for decision filtering, TLS, performance, firewall customization, and observability. The defaults (10 s poll interval, 15 m reconciliation, `pool_size: 4`) are sized for a single router handling up to roughly 30,000 active decisions; tune only beyond that scale or on low-end hardware.
